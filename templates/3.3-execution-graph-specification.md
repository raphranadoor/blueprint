# Execution Graph Specification (EG)

**Id:** `3.3` · **Prefix:** `EG` · **Stage:** 3 — Tools, memory, and graph · **Version:** `v0.1-DRAFT`

## Normative

### Purpose
Execution Graph Specification (EG) is the runtime control graph of the system. CA components become nodes in this graph, while their interfaces and relations define its edges and conditional routing rules. MDM stores and caches appear as interaction points whose state can affect routing. Nodes, routes, and execution states represent the context of multiple repositories and projects as one execution topology. EG records the TC capabilities used by each node and the accepted Spec version whose PASS covers the execution-layer properties.

### Required sections
1. Execution graph [required diagram]: the control graph of this EG version.
2. Graph nodes: CA components as nodes of this EG version, MDM stores and caches as interaction points, repository and project context, and the TC capabilities each node uses.
3. Graph edges: CA interfaces and relations, as well as relationships between repositories and projects, as the edges of this graph, in addition to routing.
4. Conditional routing: the rules by which cache outcomes and repository and project selection determine which edge is taken.
5. Execution state: the repository and project context of a run, and the execution variables that run carries.
6. Execution termination: the conditions that end a run on this graph.
7. Execution observability: the traces recorded for nodes, edges, and runs of this graph, including cache outcomes and repository and project selection.

### Acceptance gate
The TLA+ of the present Spec version is updated to include the execution-layer properties of this graph and records PASS. Once the PASS is recorded, the process proceeds to the next artifact.
