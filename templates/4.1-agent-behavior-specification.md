# Agent Behavior Specification

**Id:** `4.1` · **Stage:** 4 — Behavioral Specification and Governance · **Version:** `v0.1-DRAFT`

## Normative

### Purpose
How each agent role operates: system prompt spine per role plus reasoning, decision/tool policies, failure/stop rules, and inference defaults within AA envelopes.

### Required sections
1. Agent behavior overview (prompt vs companion policy)
2. System prompts (per agent / per AA role)
3. Reasoning framework
4. Agent decision policy
5. Tool selection strategy (only TC bound to role)
6. Interaction protocol
7. Reflection and self-correction
8. Inference parameter defaults (within AA envelopes)
9. Failure handling behavior
10. Stopping conditions (when to stop or escalate)
11. Output validation

**Excluded:** escalation handoff mechanics; governance policies; TC schemas; EG topology; Spec dynamics (referenced)

### Acceptance gate
All answers must be YES to approve:
1. Every AA role has a system prompt and matching prompt-grounded policy layers?
2. Inference defaults stay within AA temperature/top_p envelopes?
3. Tool selection uses only Tool Contracts bound to that role?
4. Pause/stop/escalate rules respect AA risk-tiered HITL tiers?
5. Output validation covers each role's declared outputs on the EG?

### Boundary
System prompts and prompt-grounded behavior; handoff mechanics → Escalation/HITL.

### Bridge
→ Escalation and Human-in-the-Loop Handoff Specification.
