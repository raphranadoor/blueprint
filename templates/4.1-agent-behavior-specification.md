# Agent Behavior Specification (ABS)

**Id:** `4.1` · **Prefix:** `ABS` · **Stage:** 4 — Behavior, handoff, and policy · **Version:** `v0.1-DRAFT`

## Normative

### Purpose
Agent Behavior Specification (ABS) defines how each AA role operates during an execution run. It gives each role the prompt, context, schema, capabilities, and model settings required for that run. ABS also specifies how the role reasons, makes decisions, interacts with the Execution Graph, reflects on its output, handles failures, terminates, and validates its results.

### Required sections
1. System prompt: the ongoing system prompt for each AA role of this ABS version, which is that role's identity, responsibilities, and operational parameters.
2. Data model and schema: the data model and schema provided to each AA role of this ABS version, and how that context is encapsulated within the window.
3. Reasoning loop: the reasoning loop that the prompt of each AA role in this version of the ABS must execute.
4. Decision-making: when each AA role of this ABS version reasons, invokes tools, pauses, or stops.
5. Capability selection: how each AA role of this ABS version selects among the TC capabilities assigned to it.
6. EG interaction: how each AA role of this ABS version interacts on the EG instance.
7. Reflection: the revise and retry behavior required of each AA role of this ABS version.
8. Failure handling: what each AA role of this ABS version does on tool, reasoning, or validation failure.
9. Termination conditions: when each AA role of this ABS version ends its turn or run.
10. Output validation: the checks applied to each AA role's outputs of this ABS version before those results return upstream.
11. Model-parameter defaults: the default values of temperature, top_p, and other changeable model settings and parameters for each role or workflow of this ABS version.

### Acceptance gate
The TLA+ of the current version of the Spec is revised to incorporate the schema of outcomes that have been decided for this behavior specification and PASS. This schema of outcomes is the schema that has been decided by the decisions and prompts of this ABS. After recording PASS, the process moves on to the next artifact.

### Boundary
System prompts and run-time behavior for each AA role. Handoff mechanics belong in HITL.

### Bridge
→ Escalation and Human-in-the-Loop Handoff Specification (HITL).
