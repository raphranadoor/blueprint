# Domain Model (DM)

**Id:** `2.1` · **Prefix:** `DM` · **Stage:** 2 — Domain and structure · **Version:** `v0.1-DRAFT`

## Normative

### Purpose
Domain Model (DM) gives the SRS concepts a common representation of the problem domain. It provides terms and relationships that domain experts, system-building agents, and agents within the system can use consistently. DM then expresses those concepts as the entities, attributes, relationships, states, invariants, and events of the system.

### Required sections
1. Domain overview: a description of the domain, including the problem domain that this ontology represents, its boundaries, and the knowledge of the domain used by the system.
2. Core entities [required diagram]: the identifiable object types of the domain ontology, whose instances persist across state change.
3. Entity attributes: the characterizing properties of each core entity as they hold in the domain.
4. Relationships between entities [required diagram]: the named associations that hold among core entities.
5. System state [required diagram]: the configuration of entity instances and their attribute values at a moment.
6. Domain invariants: properties that must hold in every valid system state.
7. Domain events [required diagram]: named occurrences that change system state, or that record that a change occurred, and the states in which each occurrence is enabled.

### Acceptance gate
All answers must be YES to approve (R1):
1. DM-C1  Can each of the named concepts have the same interpretation for the experts, the agents constructing the system, and the agents that are part of the system?
2. DM-C2  Can each core entity be paired with a specific SRS concept?
3. DM-C3  Can each entity attribute be read as a characterizing property as it holds in the domain?
4. DM-C4  Can each relationship be read as a named association that holds among core entities?
5. DM-C5  Can system state be read as the configuration of entity instances and their attribute values at a moment?

### Boundary
Domain ontology shared by experts and agents.

### Bridge
→ Formal System Specification (SPEC). First mandatory Spec PASS follows this artifact (R3).
