# Agent Architecture (including Multi-Agent Coordination Protocol)

**Id:** `3.4` · **Stage:** 3 — Architecture Specification · **Version:** `v0.1-DRAFT`

## Normative

### Purpose
Place agents at CA reasoning points on the EG. Define roles, interaction, and Multi-Agent Coordination Protocol. Structural failure paths and HITL gates; detailed behavior deferred to Stage 4.

### Required sections
1. Architectural overview
2. Agent roles
3. Agent interaction model
4. Multi-Agent Coordination Protocol (required)
5. Reasoning model
6. Context engineering architecture
7. Model provider and routing architecture
8. Inference control surface (allowed temperature/top_p ranges; defaults; override authority)
9. Tool integration via Tool Contracts
10. Memory architecture (agent-facing)
11. Execution graph (agent-facing)
12. Failure handling strategy (structural paths)
13. Risk-tiered HITL gates
14. Versioning and rollback for routing/context policy artifacts

**Excluded:** exact per-task temperature/top_p; detailed handoff dialogue (Stage 4); TC schema detail; EG redraw; memory persistence detail; Spec dynamics (referenced)

### Acceptance gate
All answers must be YES to approve:
1. Every CA reasoning point has an assigned agent role?
2. Every role maps to a defined position on the agent-facing EG?
3. Tool bindings per role limited to named Tool Contract entries?
4. Risk-tiered HITL tiers cover every action class with repo-write, deploy, or external side effects?
5. Rollback for routing/context policy artifacts defined so in-flight state is not orphaned?

### Boundary
Agent placement and coordination; prompts deferred to Agent Behavior Specification.

### Bridge
Completes Stage 3 → Stage 4 Agent Behavior Specification.
