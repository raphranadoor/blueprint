# Component Architecture (CA)

**Id:** `2.3` · **Prefix:** `CA` · **Stage:** 2 — Domain and structure · **Version:** `v0.1-DRAFT`

## Normative

### Purpose
Component Architecture (CA) defines the runtime components, interfaces, data sources, external services, and reasoning points that make up the system. Its structure must satisfy PRD and SRS requirements, respect Domain Model concepts, and remain linked to the PASS-recorded Spec.

### Required sections
1. Components [required diagram]: the runtime parts of this architecture, each related to a PRD or SRS requirement, a Domain Model concept, and a property of the Spec version that records PASS.
2. Interfaces: the interfaces those components possess.
3. Data sources and external services: the data sources and external services on which those components depend.
4. Reasoning points: the points at which agent logic is anchored (if it is needed).

### Acceptance gate
All answers must be YES to approve (R1):
1. CA-C1  Can each component be related to a PRD or SRS requirement, a Domain Model concept, and a property of the Spec version that records PASS?
2. CA-C2  Can each interface be read as belonging to the components it connects, and can each data source and external service be read as a dependency of those components?
3. CA-C3  Can each stated reasoning point be read as a point at which agent logic is anchored?

**Spec PASS:** The TLA+ of the present Spec version is updated to include this runtime architecture and records PASS. Once the PASS is recorded, the process proceeds to the next stage and artifact.

Runtime arrangement and reasoning-point markers.
