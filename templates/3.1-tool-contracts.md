# Tool Contracts

**Id:** `3.1` · **Stage:** 3 — Architecture Specification · **Version:** `v0.1-DRAFT`

## Normative

### Purpose
Living inventory of capability contracts: what may be invoked, and what the agent binds/fills/configures on CA pieces and reasoning points. Sole capability inventory.

### Required sections
1. Capability overview
2. Living capability inventory (sole named list; call + attach)
3. Interface specification per entry
4. Input validation rules
5. Output / effect schema
6. Access permissions
7. Failure modes
8. Invocation and binding policies
9. Observability and logging

**Excluded:** CA structure diagrams, Domain Model ontology, ABS, TLA+ dynamics, prompts/code

### Acceptance gate
All answers must be YES to approve:
1. Accepted CA version named?
2. Living inventory of capability contracts maintained?
3. Inventory covers invoke + bind/fill/configure?
4. Sole inventory (no parallel registry)?
5. Each entry named/specified (interface, I/O, permissions, failures, policies)?
6. Call and attach vocabulary decided?
7. Each contract bound to CA pieces?
