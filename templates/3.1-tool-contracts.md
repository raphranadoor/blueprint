# Tool Contracts (TC)

**Id:** `3.1` · **Prefix:** `TC` · **Stage:** 3 — Tools, memory, and graph · **Version:** `v0.1-DRAFT`

## Normative

### Purpose
Tool Contracts (TC) is the evolving catalogue of named capability contracts used to invoke and configure tools for CA components and reasoning points. Each contract defines its call and attachment vocabulary, interface, inputs, outputs, permissions, failure behavior, and policies. TC binds each contract to the CA components that use it and records the corresponding calls and attachments.

### Required sections
1. Catalog scope: the invocation capabilities and the filling and configuring commitments on CA components and reasoning points.
2. Capability catalog: the named list of contracts in this TC version, with the call vocabulary and the attachment vocabulary.
3. Contract fields: the interface, input, output, permissions, failures, and policies of each contract.
4. Component binding: the CA components each contract connects to.
5. Observability: what is recorded for call and attach.

### Acceptance gate
All answers must be YES to approve (R1):
1. TC-C1  Can the catalog scope be read as invocation capabilities and as filling and configuring commitments on CA components and reasoning points?
2. TC-C2  Can each contract in the named list be identified with its call vocabulary and its attachment vocabulary?
3. TC-C3  Can each contract be read as stating its interface, input, output, permissions, failures, and policies, and can it be connected to the CA components relevant to its capabilities?

### Boundary
Capability surface (call and attach) bound to CA.

### Bridge
→ Memory and Data Model (MDM). Spec PASS covering the TC catalog is recorded together with the MDM data plane.
