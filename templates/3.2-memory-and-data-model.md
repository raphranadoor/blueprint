# Memory and Data Model (MDM)

**Id:** `3.2` · **Prefix:** `MDM` · **Stage:** 3 — Tools, memory, and graph · **Version:** `v0.1-DRAFT`

## Normative

### Purpose
Memory and Data Model (MDM) defines how the system stores and provides the data consumed and produced by TC across components and nodes. It anchors stored entities in the Domain Model and records the persistence, schemas, access routes, transformations, context, system state, and caching rules that govern that data. When caching is used, MDM specifies what may be cached, for how long, and how consistency with the actual data store is maintained.

### Required sections
1. Data model at components and nodes [required diagram]: the data model as described for each component and each node.
2. Transformation rules: the rules that transform between those models.
3. Persistence: the persistence mechanism of the data TC consumes and produces.
4. Schemas: the schema definition of those stored entities.
5. Access routes: the access routes by which TC consumes and produces that data.
6. Context: the context assembled for a run, anchored in the Domain Model.
7. System state: how system state is stored and provided.
8. Caching: what may be cached, for how long, and how cached access stays consistent with the actual data store (if caching is used).
