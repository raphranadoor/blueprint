# Rule: 1.1 Problem Definition

**Stage:** 1 — Problem Definition

## Slots
Purpose · Contents · Gate · Boundary · Bridge

## Purpose
Define the problem as clearly as possible with full context. Include usecases where the problem blocks the user from moving forward.

## Required sections
1. Problem statement — clear definition with organizational or team context
2. Barrier usecases — situations where the problem blocks progress
3. Users — who feels the pain (primary and secondary where relevant)
4. Desired outcomes — solution-neutral end-states (outcome without solution)
5. Existing solutions gap — what exists and why it is not enough
6. Out of scope — what the problem is not part of

## Artifact acceptance gate
All answers must be YES to approve:
1. Problem stated clearly without presupposing an agent/system/product will be built?
2. Users who feel the pain named?
3. Organizational/team context stated; problem plausibly solvable with available resources?
4. Desired outcomes are solution-neutral end-states, not methods/designs?
5. Problem-side out of scope stated explicitly?
6. Document avoids assuming an agent/system/feature set as the solution?

## Boundary
Understand the problem without presupposing a solution.

## Bridge
→ Product Requirements Document (PRD).
