# Rule: 3.3 Execution Graph Specification

**Stage:** 3 — Architecture Specification

## Slots
Purpose · Contents · Gate · Boundary · Bridge

## Purpose
Pictorial runtime control graph from CA + Memory/Data Model. References Spec v2+ PASS for execution-layer properties (does not restate them).

## Required sections
1. Execution graph overview (named Spec version referenced)
2. Graph nodes (CA; memory stores/caches; repo/project context; TC annotations)
3. Graph edges (CA interfaces/relationships; routing; multi-repo/project crossings)
4. Conditional routing (cache outcomes; repo/project selection)
5. Execution state
6. Execution termination conditions
7. Execution observability

**Out (do not include):** parallel execution model; error handling/recovery (later); TC schema detail; agent roles; formal Spec dynamics (referenced)

## Artifact acceptance gate
All answers must be YES to approve:
1. Accepted CA named?
2. Accepted Memory and Data Model named?
3. Accepted TLA+ Spec with PASS named (v2+, execution-layer scope)?
4. Components appear as nodes?
5. Edges reflect CA interfaces/relationships and routing?
6. Memory stores/caches as interaction points; cache outcomes affect routing where applicable?
7. Multi-repo/multi-project selection explicit in routing and execution state?
8. Termination and observability specified?

## Boundary
Control-graph topology and routing — not agent prompts.

## Bridge
→ Agent Architecture. Acceptance requires Spec PASS for execution-layer scope.
