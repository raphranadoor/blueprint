# Rule: 2.1 Domain Model

**Stage:** 2 — System Design

## Slots
Purpose · Contents · Gate · Boundary · Bridge

## Purpose
Shared conceptual ontology of the problem domain. Grounds state, invariants, and events for TLA+.

## Required sections
1. Domain overview
2. Core entities
3. Entity attributes (conceptual)
4. Relationships between entities
5. System state
6. Domain invariants
7. Domain events

**Optional:** Domain operations / legal state transitions

**Out (do not include):** schemas, call catalogs, code, component diagrams, wire formats, TLA+ specs

## Artifact acceptance gate
All answers must be YES to approve:
1. Shared conceptual ontology established?
2. Core entities derived from SRS concepts?
3. Attributes as domain meaning (not storage fields)?
4. Relationships defined?
5. System state explicitly modeled?
6. Domain invariants stated?
7. Domain events stated?

## Boundary
Domain ontology — not implementation.

## Bridge
→ Formal System Specification (TLA+) v1.
