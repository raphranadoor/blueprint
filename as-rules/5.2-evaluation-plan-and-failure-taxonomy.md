# Rule: 5.2 Evaluation Plan and Failure Taxonomy

**Stage:** 5 — Implementation, Deployment, and Validation

## Slots
Purpose · Contents · Gate · Boundary · Bridge

## Purpose
How the system is judged and how failures are classified for accountable remediation.

## Required sections
1. Evaluation Plan — objectives
2. Evaluation Plan — case set (coverage, inventory, labels, inclusion/exclusion, versioning/refresh)
3. Evaluation Plan — metrics and thresholds
4. Evaluation Plan — procedures and environments
5. Evaluation Plan — pass/fail decision rules linked to case-set versions
6. Failure Taxonomy — categories (reasoning, orchestration, tool, data, governance, operational)
7. Failure Taxonomy — severity levels
8. Failure Taxonomy — detectability and signals
9. Failure Taxonomy — example instances
10. Failure Taxonomy — mapping to remediation owners

**Out (do not include):** Simulation Scenarios detail; Observability Plan dashboards

## Artifact acceptance gate
No separate YES/NO checklist. Accept when all required sections are complete, consistent with Implementation Plan sequencing, and the approver confirms.

## Boundary
Evaluation judgment and failure classification — not simulation scripts or deploy topology.

## Bridge
→ Simulation Scenarios.
