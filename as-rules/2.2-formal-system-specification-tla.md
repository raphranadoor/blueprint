# Rule: 2.2 Formal System Specification (TLA+)

**Stage:** 2 — System Design

## Slots
Purpose · Contents · Gate · Boundary · Bridge

## Purpose
Living cumulative checkable model in Temporal Logic of Actions. v1 formalizes Domain Model before Component Architecture. Later stages update and re-check the same Spec.

## Required sections
1. Specification overview — living cumulative model; named inputs; stage scope
2. State variables
3. Initial state
4. Actions (state transitions)
5. Safety properties
6. Liveness properties
7. System behavior specification (composed Spec)
8. Model-checking configuration — tool, properties, finite bounds/assumptions
9. Model-checking results — PASS evidence for this version under §8
10. Version and stage-scope record — Spec version id; stage scope; later stages extend this Spec

**Out (do not include):** Tool Contracts detail, prompts, CA diagrams, EG topology, schemas/APIs/code

## Artifact acceptance gate
All answers must be YES to approve:
1. TLA+ named and expanded (Temporal Logic of Actions) in usable form?
2. Inputs named (Domain Model for v1; plus EG/other as applicable later)?
3. State variables defined for this version's scope?
4. Initial state specified?
5. Actions specified for this version's scope?
6. Properties to be checked stated?
7. Verification approach stated?
8. Contents §9 records PASS under §8 configuration?
9. Version record states stage scope and that later dynamics extend this Spec?

**Hard rules:** FAIL ⇒ Gate NO. v1 PASS before Component Architecture. Stage 2+ exit needs Spec PASS for cumulative scope. EG acceptance needs Spec v2+ PASS for execution-layer scope.

## Boundary
Formal dynamics + PASS evidence; others reference Spec versions.

## Bridge
v1 PASS → Component Architecture; later PASS → stage-exit / EG acceptance.
